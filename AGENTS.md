# Разработка пакета

Перед изменением CSS-компиляции прочитать
[документ о локальной копии mrclay CSS](src/vendor/mrclay/README.md).
Сохранять лицензию, происхождение и совместимость результата. Не возвращать
обязательную зависимость mrclay/minify ради CSS и не добавлять LESS-компилятор.
Переход на другой CSS-движок — отдельная задача с проверкой совместимости.

После изменений запускать PHP lint и tests/css-compatibility.php; HTML-изменения
проверять также tests/html-compressor.php. В composer.lock потребителей ничего
не менять механическим удалением записей: зависимости обновляет Composer.

Склеенные файлы называются по содержимому, набор исходников ссылается на них
через `.index/<ключ>` (README, «Compiled files and cleanup»). Не возвращать имя
по списку URL исходников и `?v=filemtime`: это давало копии после каждой
выкладки. Путь попадания в готовый файл выполняется на каждой странице —
держать его без чтения содержимого и без записи чаще `usageTouchInterval`.
Признак использования для очистки — mtime индекса и файла, не atime/ctime.
Отметка и запись склейки — под общей блокировкой `.index/.lock`, удаление —
под исключительной с перепроверкой отметки; `touch()` без проверки
существования под блокировкой не вызывать (он создаёт пустой файл). Очистка
трогает только штатные имена и ничего не удаляет из каталога, который не
смогла прочитать. Новая настройка, меняющая содержимое, — в `getSettingsHash()`.
Изменения склейки и очистки проверять tests/compiled-files.php.
